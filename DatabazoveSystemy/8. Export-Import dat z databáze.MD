# Export/Import dat z databáze - příklady pro různé datové soubory, rozdíl mezi exportem struktury databáze a exportem dat, proces migrace dat, význam a důvody

## Reálné scénáře: Kdy a proč to vlastně děláme
- Neděláme to jen tak
- Integrace systému = Pravidelná výměna dat mezi např účetním softwarem a db
- Analytické zpracování (Data Warehousing) = Extrakce dat z produkčních systému pro potřeby ETL procesů a následnou analýzu v datových skladech
- Archivace dat: Ukládání historických, provozně neaktivních záznamů do nezávislých dlouhodbě čitelných formátů (např. CSV, XML)
- Vývoj a testování: Přenos reálných nebo anonymizovaných datových sad do testovacího a vývojového prostředí

## Rozdíl mezi exportem struktury a exportem dat
- Zásadním konceptem je striktní oddělení definice datové struktury od samotného obsahu
- Při exportu je nutné:
  - **Export struktur** (DDL – Data Definition Language)
    - Tento proces generuje skript obsahující příkazy pro vytvoření db objektů
    - Skript definuje názvy sloupců, datové typy, PK, FK, indexy a integritní omezení
    - Neobsahuje uživ. záznamy
  - **Export dat** (DML - Data Manipulation Language)
    - Proces extrahující samotné záznamy
    - Může nabývat formy .txt, .csv, .json, nebo SQL příkazů
  - **Závislost při importu** 
    - Platí striktní pravidla, že nelze importovat data do db, aniž by v ní předem existovala odpovídající struktura
    - DB nástroje umožňují vygenerovat kombinovaný skript, který nejprve vytvoří strukturu a následně do ní vloží data

## Podporované datové formáty a jejich specifikace
- Volba exportního a importního formátu závisí na cílové platformě
- Typy:
  - **Micrsoft SQL Server** (MSSQL):
    - Nativně podporuje proprietární formáty společnosti (Excel, Access)
    - Univerzální formát CV a SQL skript
    - Pro import JSONu je často nutná předchozí transformace nebo využití specifických T-SQL funkcí
  - **MySQL**
    - Nepodporuje microsoft produkty
    - Standardem pro přesun dat jsou formáty CSV a JSON
  - **Oracle Database**
    - Podporuje mimo jiné formáty CSV a XML
    - Klade důraz na explicitní definici kódování znakové sady (Encoding, např UTF-8) aby nedošlo k porušení diakritiky
- Ačkoliv je CSV nejuniverzálnějším formátem, přináši rizika spojená s parsováním
- Administrátor musí striktně definovat oddělovače sloupců a textové kvalifikátory, aby systém chybně neinterpretoval interpunkci uvnitř dat

## Zajištění konzistence při procesu importu
- Samotný import (typicky prováděn přes Import Wizard) je kritickou operací při které db stroje (Engine) validuje vkládaná data proti existující struktuře
- Před importem je nutné data připravit a ověřit
- Časté příčiny selhání importu jsou:
  - Neshoda datových typů (Poku vložení čísla do varchar)
  - Porušení doménové integrity (Překročíme limit znaků)
  - Porušení referenční integrity (Vkládání dat sirotka)

## Proces migrace
- Zatímco export / import je dílčí operace, migrace dat přesune komplexně všechna data z jednoho místa na druhé
- Proces se dělí do několika fází:
  - Analýza a mapování (Data Mapping) - Detailní srovnání struktury zdroj. a cíl. db
  - Extrakce - Export dat ze starého neboli zdroj systému
  - Transformace a čištění - Softwarová úprava dat, zahrňuje odstraňování duplicit, normalizace formátu
  - Načtení (Load/Import) - Fyzické vložení upravených dat do cílového systému
  - Verifikace - Kontrola dat. integrity po migraci, aby bylo garantované, že nedošlo k žádné ztrátě
