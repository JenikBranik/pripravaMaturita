# Architektura databázových systémů - základní struktura, popis jednotlivých bloků a jejich činnost, správa, služby, systémový katalog

## Fyzická a logická architektura systému
- Architektura databázového systému lze rozdělit na úroveň fyzického uložení souborů a úroveň logického procesů
- Moderní systémy, jako je MySQL, jsou vysoce flexibilní a multiplatformní

#### Fyzická architektura (Adresářová struktura)
- Fyzicky se instalace databáze dělí na základní (Base) a datové (Data) adresáře:
- **Base directory**:
  - Obsahuje nezbytné systémové knihovny
  - Dokumentaci a definiční soubory
- **Data directory**:
  - Představuje samotné jádro uložení
  - Obsahuje stavové soubory, databázové logy a vlastní podadresáře s datovými a indexovými soubory včetně objektových struktur
  - Dále obsahuje spustitelné programy nezbytné pro správu, jako jsou MySQL, mysqladming,....

#### Logická architektura a zpracování dotazu (Moduly serveru)
- Základem serverové části je tzv. daemon, který funguje jako vícevláknový proces spravující příchozí relace od klientů.
- Aplikace komunikuje se serverem prostřednictvím konektorů či pluginů
- Když klient odešle SQL dotaz, prochází následujícími bloky:
  - **Connection / Thread Handling** (Správa spojení):
    - Modul, který přijímá požadavek, ověřuje uživatelská oprávnění a zajišťuje autentifikaci uživatele.
    - Zajišťuje multitasking a přiděluj každému klientovi vlastní vlákno.
  - **Parser** (Analyzátor):
    - Program, který provádí syntatickou kontrolu příchozího SQL příkazu a analyzuje klíčová slova
    - Každému SQL příkazu vygeneruje a přidělí unikátní identifikátor (SQL-ID)
    - Parser rověž kontroluje, zda stejný příkaz nebyl již v minulosti syntakticky zkontrolován
  - **Optimalizér (Optimizer)**
    - Kritická komponenta, která na základě metadat vytváří tzv. exekuční plán
    - Účelem optimalizéru je určit nejefektivnější a nejrychlejší cestu, jak data ze systému žískat (Organizace pořadí čtení tabulek či výběr vhodných indexů) a to pro každý konkrétní uložený engine

#### Paměťová struktury a služby (Cache systém)
- Pro urychlení práce využívá databázový server systém vyrovnávacích pamětí (Cache), které minimalizují nutnost čtení z pomalého fyzického disku:
  - **Query Cache** (Paměť dotazů)
    - Obsahuje výledky již zpracovaných identických dotazů
    - Tato paměť je sdílená pro všechny relace, takže výsledky dotazu jednoho klienta může být využit klientem jiným
    - Pokud analyzátor (Parser) zjistí shodu, přeskočí fázi optimalizace i fyzického čtení a rovnou vrací výsledek z cache
  - **Metadata Cache**
    - Paměť v RAM, která uchovává informace o databázových objektech, statistiky a aktuálně používaná metadata
    - Data zde zůstávají, dokud nejsou v důsledku frekventovanějších dotazů nahrazena novými záznamy
  - **Key Cache** (Paměť klíčů/indexů)
    - Ukládá identitu indexů tabulek
    - U malých indexů obashuje kompletní strukturu včetně dat, u rozsáhlých indexů obsahuje pouze adresní strukturu, zatímco samotná data jsou čtena z disku.
    
#### Storage Engines (Uložené moduly)
- Moderní architektura (Typická pro MySQL) odděluje vrstvu zpracování SQL od vrstvy fyzického uložeí dat.
- Tyto moduly (Engines) spravují fyzická data a zodpovídají za provedení dotazů na diskové úrovni.
- Administrátor volí typ enginu podle požadovaného nasazení:
  - **InnoDB**:
    - Standardní engine por uživatelská data
    - Podporuje plné transakční zpracování, zamykání na úrovni řádku (row-level locking) a ukládá data do logických struktur tvořených více datovými soubory
  - **MyISAM**:
    - Netransakční engine optimalizovaný pro extrémně rychlé čtení
    - Pro urychlení využívá výhradně Key Cache, Metadata Cache a Query Cache
  - **Memory Engine**
    - Netransakční úložiště v operační paměti pro velké objemy dočasných dat
    - Dovoluje základní operace a využívá zamykání na úrovni celých tabulek
  - **Další varianty**
    - Příkladem je CSV Engine, který ukládá data přímo v textovém formátu CSV
    - Nebo NDB, což je síťová databáze ukládající data v distribuovaných clusterech

#### Systémový katalog (Data Dictionary)
- Systémový katalog funguje jako informční centrum neboli "mozek" celé db.
- Jedná se o soubor speciálních systémových tabulek, které si automaticky vytváří a spravuje samotný db systémy.
- Katalog obsahuje metadata:
  - existujicích tabulek 
  - jejich atributy 
  - omezení
  - Specifikace dat. typů
  - Uživatelská práva a informace o fyzickém umístění souborů na disku
- Z pohledu SQL standardu je toto rozhraní definováno jako tzv. Informační schéma, které zajišťuje sjednocený uživatelský přístup k těmto metadatům napříč různými platformami
